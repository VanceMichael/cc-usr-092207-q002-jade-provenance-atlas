# 海外良渚玉器谱系库

整理海内外良渚玉器身份、流转记录与可修订学术判断。

## 领域资料

`contracts/domain.schema.json` 规定共享资料结构，`fixtures/domain.json` 保存不含真实个人信息的示例。当前参与方包括考古研究人员、海外博物馆、文献整理人员、公共查询用户。

资料所依据的领域事实如下：

- 欧美多家机构收藏良渚玉器且部分早期年代判断有误
- 研究院正在搭建海内外良渚玉器数据库
- 一些器物的更早出土与流转经历已经难以确定

## 谱系记录

`contracts/record.schema.json` 规定单件器物的谱系记录结构，`fixtures/record.json` 为虚构示例（早期图录误判周汉、后被改定良渚，并含候选同一性关联与未公开图像）。设计要点：

- 器物物理身份（`artifact`）与学术判断（`claims`）分离，避免按名称合并误认同一件器物
- 尺寸、纹饰、修整痕迹等观察（`observations`）、历次定名（`namings`）、流转事件（`provenance_events`）、图像权利（`images`）逐条保存来源与置信度
- 同一器物、文化归属、年代、曾属某收藏等结论一律表示为 `claims`，必须带回提出者、来源与有效时间；新证据可建立候选关联（`candidate`）或推翻旧判断（`superseded`/`refuted`），旧记录只标记失效、不删除
- 相互矛盾的目录记载并列保存，以置信度区分，供学者比较竞争假说
- `rights` 由馆藏机构设定默认可见性与按栏目/条目、按受众的授权策略；`src/provenance.py` 的 `view_for` 生成公众视图，未授权内容（含策略本身）不出现

## 本地校验

仓库内的读取模块负责校验示例资料的领域标识、版本、参与方、事实和约束；谱系记录模块额外校验来源引用、失效标记与授权策略目标。运行项目自带测试即可检查这些基础资料能够稳定读取。仓库不保存账号、密钥、连接串或真实身份信息。
